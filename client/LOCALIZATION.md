# Localization

The frontend UI is available in six languages. You can switch language at any time with the selector
in the header, including on the login page. The choice is remembered in `localStorage`. The first
time you visit, the browser's language is used if it is one of the supported ones, otherwise English.

| Code | Language | Script | Direction | Plural forms (CLDR) | Digits / calendar |
| --- | --- | --- | --- | --- | --- |
| `en` | English (default, fallback) | Latin | LTR | one, other | Western, Gregorian |
| `fi` | Suomi (Finnish) | Latin | LTR | one, other | Western, Gregorian |
| `fa` | فارسی (Farsi / Persian) | **Arabic (non-Latin)** | **RTL** | one, other | **Persian ۰–۹, Solar Hijri** |
| `ja` | 日本語 (Japanese) | **Kanji / kana (non-Latin)** | LTR | other | Western, Gregorian |
| `ru` | Русский (Russian) | **Cyrillic (non-Latin)** | LTR | one, few, many, other | Western, Gregorian |
| `mn` | Монгол (Mongolian) | **Cyrillic (non-Latin)** | LTR | one, other | Western, Gregorian |

> The non-English translations are first drafts and should be reviewed by a native speaker.

## Framework

We don't use a third-party i18n library. The frontend has no bundler and no runtime dependencies,
so localization uses two pieces:

1. **The ECMAScript Internationalization API (`Intl`)**, which is built into every modern browser:
   - `Intl.DateTimeFormat` formats dates and times. Each locale's own calendar and digits are used, so
     Farsi gets Solar Hijri dates in Persian digits.
   - `Intl.NumberFormat` formats counts, percentages (`style: "percent"`) and the countdown timer.
   - `Intl.PluralRules` picks the right plural form, e.g. Russian 1 занятие / 3 занятия / 5 занятий /
     21 занятие.
2. **A small message lookup in [`js/i18n.js`](js/i18n.js)** (~150 lines including comments). Strings
   are kept in one JSON file per language under [`locales/`](locales/).

### API (`js/i18n.js`)

| Function | Purpose |
| --- | --- |
| `initI18n()` | Loads `en.json` (the fallback) and the saved or browser language. Called once by the router before the first page renders. |
| `setLanguage(code)` | Loads that language and saves the choice. Sets `<html lang dir>` and `document.title`, and re-translates the static `data-i18n` elements in `index.html`. |
| `t(key, params)` | Looks the key up in the current language, then English, then returns the key itself, so a missing string is visible. `{name}` placeholders are filled from `params`, and numbers are formatted for the locale. If the entry is an object of plural forms, `params.count` chooses the form. |
| `formatNumber(n, opts)`, `formatPercent(ratio)`, `formatDate(ms, opts)`, `formatTime(ms)` | Thin wrappers around `Intl` that use the current language. |
| `translateServerError(message)` | The backend replies in English. Known messages are mapped to `server.*` keys, and unknown ones are shown as they are. `api.js` calls this, so `err.message` is always already translated. |
| `LANGUAGES` | The supported languages: each language's name in that language, and its text direction. |

### Message format

```json
{
  "teacher.session.activeExpiresIn": "Active — expires in {time}",
  "common.studentCount": { "one": "{count} student", "other": "{count} students" }
}
```

Keys are flat and namespaced by screen (`login.*`, `teacher.attendance.*` …). Shared strings use
`common.*`, attendance statuses use `status.*`, and server errors use `server.*`. A plural entry
must contain the `other` form plus whatever forms `Intl.PluralRules` produces for that language.

### How the language switch works

`js/router.js` fills the `<select id="lang-select">` from `LANGUAGES`. When it changes, the router
calls `setLanguage()` and then re-runs the current route. The page renders again in the new language,
and its cleanup function still runs first, so the teacher session page's polling restarts cleanly.

## Numbers, dates and tables

- **Dates and times:** session dates in both attendance views, confirmation times and roster times
  all use `formatDate`/`formatTime`. There are no hardcoded `toLocaleString([])` calls, so the format
  follows the selected UI language, not the browser's.
- **Numbers:** session numbers, counts, "x/y" totals, percentages and the `m:ss` countdown are all
  formatted with `Intl.NumberFormat`.
- **The attendance code** stays in ASCII digits with `dir="ltr"`, because that is what students type.
  The code input also accepts Persian (`۰–۹`) and Arabic-Indic (`٠–٩`) digits and converts them to
  ASCII, so a student on a Farsi keyboard can type `۴۲` for 42.
- **Tables:** the teacher's attendance table translates its headers, the status badges, their
  one-character short forms and the legend. Its layout mirrors in RTL (see below).
- **Excel export:** only the downloaded file name is localized. The `.xlsx` content is generated by
  the server and stays in English.

## RTL support

`setLanguage()` sets `<html dir="rtl">` for Farsi. The layout uses Tailwind's **logical** utilities,
which follow the text direction, instead of physical ones:

| Instead of | Use |
| --- | --- |
| `left-0` / `right-0` | `start-0` / `end-0` |
| `pl-*` / `pr-*`, `ml-*` / `mr-*` | `ps-*` / `pe-*`, `ms-*` / `me-*` |
| `text-left` / `text-right` | `text-start` / `text-end` |

Flex rows, `justify-between` and `gap` flip automatically. In Farsi, the sticky student column of
the attendance table sits on the right and the Total column on the left. The "←" in back links has
`rtl:-scale-x-100` (mirrored), so it points the right way. Emails, the code display and the code input are
marked `dir="ltr"`.

## Adding a language

1. Copy `locales/en.json` to `locales/<code>.json` and translate the values. Keep the keys, the
   `{placeholders}` and the plural form names. Add any extra forms the language needs (see the
   [CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)).
2. Add `<code>: { name: "<native name>", dir: "ltr" | "rtl" }` to `LANGUAGES` in `js/i18n.js`.
3. Check that the key sets match:

   ```sh
   node -e 'const f=require("fs"),en=Object.keys(JSON.parse(f.readFileSync("locales/en.json")));for(const l of f.readdirSync("locales")){const k=Object.keys(JSON.parse(f.readFileSync("locales/"+l)));console.log(l,en.filter(x=>!k.includes(x)))}'
   ```

## Adding a string

Add the key to `locales/en.json` first, use it with `t("…")` in the page, then add it to the other
locale files. Never interpolate user data (names, course names) into a translation with `innerHTML`
without `escapeHtml()`. Translations themselves are trusted, but `{course}` values come from users.
